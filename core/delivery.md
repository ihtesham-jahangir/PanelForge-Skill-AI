# Delivery Standards

A delivery report must separate:

- Implemented and verified.
- Implemented but not verified.
- Documented only.
- Deferred or blocked.

Include files changed, commands run, results, known limitations, security findings, and follow-up work. Never label an unexecuted test as passing.

Also list non-generated work: external credentials and provider setup, cloud
resources, production migrations, backup/restore drills, monitoring and
on-call ownership, legal/compliance review, security assessment, migration
sign-off, and human product decisions. Use the capability states from
[`quality/capability-gaps.md`](../quality/capability-gaps.md).
