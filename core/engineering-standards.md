# Engineering Standards

- Use the repository's formatter, linter, type checker, and test runner.
- Keep changes cohesive and backwards-compatible unless a behavior change is explicit.
- Validate at trust boundaries and return actionable errors using existing conventions.
- Prefer typed domain objects and named constants over unchecked casts and magic values.
- Make state transitions explicit and test invalid transitions.
- Keep secrets out of source, logs, fixtures, and documentation.
- Update directly related documentation and migration notes.
