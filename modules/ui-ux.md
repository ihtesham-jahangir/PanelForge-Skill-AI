# UI/UX Engineering

Start with personas, user journeys, information architecture, and business vocabulary. Define navigation and content hierarchy before styling. Every screen should state its primary task and success feedback.

## Required component behavior

Navigation, sidebars, headers, forms, tables, charts, dialogs, drawers, notifications, filters, search, pagination, empty states, and loading skeletons must define all standard states. Keyboard focus must be visible and logical. Errors should be local, specific, recoverable, and announced where appropriate.

Responsive designs must specify mobile, tablet, and desktop behavior rather than merely shrinking desktop. Tables need a small-screen strategy, such as prioritised columns, row details, or horizontal scrolling with an accessible label.

Avoid generic “three cards and a chart” dashboards. Use domain-specific metrics, workflows, permissions, and empty states. Validate contrast, target size, headings, labels, keyboard order, reduced motion, and screen-reader semantics.
